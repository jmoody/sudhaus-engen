# Domain docs

## Before exploring

- Read `GLOSSARY.md` at the repo root, if it exists.
- Read relevant architecture decision records in `docs/adrs/`.

If either is absent, proceed without calling out its absence. The `domain-modeling` skill can create domain documentation when terms or decisions are resolved.

## Vocabulary and decisions

Use the glossary's terminology when naming domain concepts in output. If a concept is missing, reconsider whether it belongs in the domain or note the gap for `domain-modeling`.

Record new ADRs in `docs/adrs/` using `adr-author`. Flag any conflict with an existing ADR rather than silently overriding it.
